# 🚨 即時災防通報與決策幕僚系統

> **基於 Serverless 前端架構與多模型 AI 備援的雙端災防通訊協作平台**

## 一、問題 (Problem)

在現行的災害現場（如颱風、地震、土石流）救援行動中，前線人員與指揮中心之間的資訊傳遞面臨三大痛點：

1. **資訊破碎與時間差**：高度依賴 LINE 或無線電，指揮官需手動將文字/語音災情重新標記到實體或數位地圖上，耗時且易出錯。
2. **惡劣環境操作困難**：前線人員在狂風暴雨或穿戴防護裝備時，難以進行繁瑣的打字輸入，也無法緊盯螢幕查看最新指令。
3. **情資過載與決策癱瘓**：當多組人馬同時回報海量非結構化資訊（文字、照片）時，指揮中心難以快速抽絲剝繭，判斷何處有傷亡及物資需求的優先順序。

## 二、解法 (Solution)

本作品打造了一套「免安裝、點開即用」的雲端雙端協作系統，精準擊破上述痛點：

1. **毫秒級地圖同步 (Auto-Sync)**：捨棄人工轉錄，透過 Firebase Realtime Database，前線一有動作（移動、點擊狀態），指揮端地圖會在 0.1 秒內自動畫出光點與軌跡。
2. **語音強制廣播 (TTS Command)**：指揮端下達「撤退」或「警報」時，前線手機會無視畫面狀態，直接發出震動與大音量語音朗讀指令，確保在高壓環境下「指令必達」。
3. **AI 決策幕僚 (AI Staffing)**：導入 LLM 大語言模型，前線只需輸入或口述簡短備註，系統自動轉譯為結構化的 JSON 報表（傷亡數、急迫性），並自動彙整為全域戰情總結。

## 三、元件設計 (Component Design)

本專案採用 **純前端 (Pure Frontend)** 搭配 **BaaS (Backend as a Service)** 架構，分為四大核心元件：

* **📱 前線通報端 (`index.html`)**：
* **Input**：Geolocation API (座標)、設備電量、一鍵環境標籤 (如：路坍/傷患)、現場照片 (FIFO 機制)。
* **Process**：資料封裝後即時 `update` 至雲端；並監聽雲端全域指令。
* **Output**：DOM 狀態反饋、震動 (Vibration API)、語音播報 (Web Speech API)。


* **💻 指揮分析端 (`map.html`)**：
* **Input**：全域人員座標與狀態推播、指揮官戰術指令 (撤退/導航派發)。
* **Process**：使用 **DOM 防閃爍 (State Diffing)** 技術比對狀態變更；Leaflet.js 繪製軌跡圖層。
* **Output**：即時戰情儀表板、動態人員卡片、路徑導航連結生成。


* **⚡ 即時通訊中樞 (Firebase)**：
* 擔任系統神經網路，使用 JSON Tree 結構儲存節點狀態，取代傳統 RESTful API 輪詢，實現雙向 WebSocket 低延遲傳輸。


* **🧠 AI 閘道器與備援機制 (OpenRouter)**：
* 實作**多模型備援 (Fallback Strategy)**。首選模型 (`Nemotron`) 失敗時，自動切換至備用模型 (`Gemini`)，確保高壓救災環境下 AI 解析服務不中斷。



## 四、使用情境 (Use Case Scenario)

**【情境：山區土石流搜救行動】**

1. **任務展開**：搜救員「阿強」用手機瀏覽器點開網址輸入 ID。指揮官「陳主任」的電腦大螢幕地圖上立刻亮起阿強的藍色光點，並開始記錄軌跡。
2. **遇險通報**：阿強遭遇道路中斷且發現受困者。他在狂風中點擊「路坍」、「有傷患」按鈕，並用語音輸入：「兩人受傷，需要擔架」。
3. **AI 判讀與調度**：陳主任的地圖上，阿強的光點轉為紅色警示。AI 已自動將備註轉換為 `{"casualties": "2人", "needs": ["擔架"], "urgency": "高"}` 顯示在面板上。陳主任立刻在地圖點擊，發送「派發路徑」引導其他隊員前往支援。
4. **緊急撤退**：上游水壩緊急洩洪，陳主任點擊「全體撤退」。所有前線搜救員的手機立刻大聲播報：「全體人員立即撤退！」，確保人員安全撤離。

## 五、預期效益 (Expected Benefits)

1. **跨單位無縫整合 (無痛導入)**：無需經由 App Store 審核與安裝，任何單位的搜救員只要有瀏覽器即可掃碼加入同一張戰情地圖。
2. **通訊零時差，提升存活率**：將傳統「通報 -> 紀錄 -> 標記 -> 下令」的 5-10 分鐘流程，壓縮至 **1 秒內**自動完成，為搶救生命爭取黃金時間。
3. **降低指揮官認知負荷**：透過 AI 萃取關鍵字與生成總結報告，指揮官能專注於「戰術決策」，而非陷入雜亂的 LINE 訊息泥沼中。
4. **系統極限環境生存率高**：內建 AI 雙模型自動備援與極簡傳輸 payload，即使在 3G 弱網環境下依然能維持核心座標與標籤的傳輸。

## 六、延伸可能 (Future Extensions)

本系統具備高度擴充彈性，未來可進一步整合以下技術：

1. **無網狀網路 (Mesh Network) 支援**：導入 WebRTC 技術，在災區基地台全毀的情況下，透過手機間的藍牙/Wi-Fi 直連進行點對點 (P2P) 座標接力傳輸。
2. **IoT 生理數據整合**：透過 Web Bluetooth API 介接搜救員的智慧手錶，將心跳、血氧等生理數據一併回傳，實現「人員健康生命監控」。
3. **無人機 (UAV) 視角接入**：將無人機的即時影像與座標視為「特殊節點」接入 Firebase，為指揮中心提供空拍圖層疊加的立體戰情。

### 🚀 快速啟動指引 (Quick Start)

本專案為 Serverless 架構，無須啟動本地後端伺服器。

1. 克隆本專案至本地端。
2. 在 `firebase-config.js` 填入您的 Firebase 專案設定。
3. 在本地測試時，將 `index.html` 與 `map.html` 內的 `OPENROUTER_API_KEY` 替換為您的測試金鑰。
4. 直接使用瀏覽器開啟 `index.html` (前線端) 或 `map.html` (指揮端) 即可運行。
5. **雲端部署**：請使用預設的 GitHub Actions (`deploy.yml`) 進行部署，並於 GitHub Secrets 設定 `OPENROUTER_API_KEY` 以策安全。
